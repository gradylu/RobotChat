## 1. 项目概述

RobotChat 是运行在机器人本体的**全双工语音交互系统**。系统在麦克风常开采集的同时进行语音播报，支持用户在机器人说话过程中随时插话，并实现毫秒级的即时打断。

系统采用流式 ASR / LLM / TTS 三段式级联管线，所有模型与设备接入均以可插拔驱动实现，通过配置文件即可切换模型厂商（本地自建或云端 API），无需改动业务代码。

系统以 **Docker 容器化**形式交付，与机器人已有的 ROS2 环境共存运行，并对外提供 WebUI 控制台用于实时观测、运行控制与运维配置。

## 3. 术语表

| 术语 | 定义 |
| --- | --- |
| 全双工 Full-Duplex | 音频采集与播放同时进行，互不阻塞 |
| Barge-in | 机器人在播报时，用户说话触发的即时打断行为 |
| 自打断 | 机器人把自身扬声器输出误判为用户语音导致的错误打断 |
| VAD | Voice Activity Detection，语音活动检测 |
| 端点 / Endpointing | 判定用户一句话说完了（尾点静音判定） |
| Partial / Final | ASR 流式识别的中间结果 / 该句最终结果 |
| Turn | 一轮交互，从用户起音到机器人播报结束 |
| turn_id | 单调递增的轮次标识，用于丢弃陈旧事件、防乱响应 |
| 保护窗口 | 播报开始后的一小段时间内不判定打断，用于规避残余回声 |
| Provider | 某一类模型能力的可插拔驱动实现（ASR / LLM / TTS） |
| 热切换 | 运行时不中断服务地更换驱动 |
| 熔断 | 连续失败达阈值后主动停止调用该 provider，避免雪崩 |
| 唤醒词 Wake Word | 用于激活交互的特定口令，待机态常驻本地检测 |
| KWS | Keyword Spotting，唤醒词检测 |
| 待机态 | 未激活交互的空闲状态，仅唤醒词检测运行 |
| 会话活跃期 | 唤醒后无需重复唤醒的时间窗口，窗口内可自由多轮对话与打断 |
| 语言 Language | 交互所用语种，本系统支持 `zh`（普通话）与 `en`（英语） |
| 方言 Dialect | 中文的地域变体，本系统支持 `yue`（粤语）`dongbei`（东北话）`wuhan`（武汉话）`shanghai`（上海话）`tianjin`（天津话） |
| 语种标记 lang | 每个轮次记录的识别语言 / 方言标识，用于驱动选路、音色选择与提示词约束 |
| 中英混说 Code-switch | 同一句内中文与英文交替出现，须整体识别而非按语言切段 |
| 语言能力协商 | ASR / TTS 驱动声明其支持的语言集合，编排层据此选路或降级 |
| 设备适配层 AudioDeviceAdapter | 屏蔽各机型 ROS2 音频接口差异的抽象层，采集与播放分为两个独立契约（FR-16） |
| 机型 Profile | 描述某一机器人型号音频接口细节的配置文件（话题 / 服务、消息类型、采样率、声道、停播方式等），换机型只换 Profile |
| 发行版矩阵 ROS_DISTRO | ROS2 发行版本（Humble / Jazzy）对应的镜像构建与依赖组合，同一份代码分别构建两套镜像标签 |
| 算力分层 | 模型按算力位置分工：ASR / TTS / VAD / AEC / KWS 在本体，LLM 与知识库在边端或云端（CON-12） |
| 知识库检索 RAG | 从外置知识库检索相关片段并注入提示词，使回答基于领域知识；抽象为 `KnowledgeRetriever` |
| AEC 模式 | `auto` / `hardware` / `software` / `none` 四种回声消除工作方式，按机型能力自动或手动选择（CON-13） |

## 5. 功能需求

### FR-1 全双工音频接入与输出

- FR-1.1 系统须从机器人麦克风阵列获取实时音频流，采集参数（采样率、位深、声道数、设备标识）均可配置。
- FR-1.2 系统须将播报音频输出到机器人扬声器，输出参数可配置。
- FR-1.3 采集与播放必须是**两条独立并发的链路**，播放过程中采集不得中断（全双工前提）。
- FR-1.4 音频链路须具备缓冲能力，屏蔽设备侧的采集与播放抖动。
- FR-1.5 系统须能获取「即将播放的音频」作为回声消除参考信号。
- FR-1.6 音频链路断开后须自动重连，重连期间系统进入降级状态而非崩溃。
- FR-1.7 系统须支持不依赖实机设备的音频自测模式（本地文件回放 + 录制），用于开发与现场诊断。
- FR-1.8 系统须提供音频链路自检能力（采集是否有数据、播放是否出声、端到端回环测试）。

### FR-2 语音活动检测与端点判定

- FR-2.1 VAD 在**会话活跃期内**（聆听、播报、执行等状态）**始终运行**（这是「边听边说 + 秒打断」的前提）；待机态由唤醒词检测常驻、VAD 降为低功耗能量门控；关闭唤醒词（FR-14.8）时不存在待机态，VAD 与 ASR 按活跃期规则常开。
- FR-2.2 须能自适应估计环境噪声底，动态调整判定门限；环境噪声阶跃后须在 3 秒内收敛到新门限（误差 ±3dB），并输出收敛判定指标。
- FR-2.3 须支持「起音确认」：连续多帧判定为语音才认为用户开始说话，抑制瞬时噪声误触发。
- FR-2.4 须支持「尾点检测」：静音持续达到阈值即判定一句话结束，阈值可配置。
- FR-2.5 须有最大语音时长保护，超时强制端点，避免长时噪声导致状态滞留。
- FR-2.6 VAD 引擎须可插拔替换。

### FR-3 流式 ASR

- FR-3.1 须以流式会话方式接收音频并持续产出 partial 结果。
- FR-3.2 端点触发后须产出该句的 final 结果。
- FR-3.3 ASR 会话在被打断后须保持存活（热流），使打断后能立即继续识别，降低二次响应延迟。
- FR-3.4 须支持热词 / 上下文偏置，用于机器人指令、设备名、人名等专有名词的识别准确率提升。
- FR-3.5 识别结果须带时间信息，供回声剔除与打断判定使用。
- FR-3.6 须至少支持本地驱动与云端驱动两类实现，可在配置中切换。
- FR-3.7 须支持 `zh`（普通话）、`en`（英语）两种语言，以及粤语、东北话、武汉话、上海话、天津话 5 种中文方言的识别（FR-15）。
- FR-3.8 须能对中英混说（code-switch）的整句进行识别，不得强制按语言切段。
- FR-3.9 识别结果须携带语种 / 方言标记（`lang`），供下游选路与播报使用。

### FR-4 流式 LLM

- FR-4.1 须以 token 流方式输出，首个 token 即启动下游的句切分与 TTS 流式合成（满足 FR-4.3），不得等待整句生成完成。
- FR-4.2 须支持 Function Calling / Tool Use 协议，用于任务指令的下发。
- FR-4.3 须支持将流式输出按句切分后送 TTS，平衡首响延迟与播报韵律。
- FR-4.4 须支持系统提示词模板化，机器人角色与能力说明可由配置注入。
- FR-4.5 收到取消信号后须立即中止生成并停止下游。
- FR-4.6 提示词须携带当前语种 / 方言上下文，并要求模型以**同语言（必要时同方言）**回应；专有名词、设备名保持原文。
- FR-4.7 须支持**知识库检索增强**：在组装提示词前调用外置知识库检索服务（边端或云端），将命中的片段按预算注入提示词；检索失败或超时须降级为无增强对话并在日志 / WebUI 标记，不得阻塞整轮对话（A5、FR-13.11）。
- FR-4.8 知识库检索服务须可插拔（抽象为 `KnowledgeRetriever`），支持切换实现与关闭；命中片段须可追溯（记录来源与得分）以便排查错误回答。

### FR-5 流式 TTS

- FR-5.1 须支持按句 / 按块流式合成，首块音频尽快可播放。
- FR-5.2 输出音频格式与采样率可配置，须可直接送扬声器播放。
- FR-5.3 音色、语速、音量等参数可配置。
- FR-5.4 收到取消信号后须停止合成并清空未播放的音频队列。
- FR-5.5 须至少支持本地驱动与云端驱动两类实现，可在配置中切换。
- FR-5.6 须支持按语种选择音色（中文 / 英文），音色与语言的映射可配置。
- FR-5.7 方言播报须有明确的降级策略：目标方言无可用音色时，降级为普通话播报并在 WebUI 标记（不得静默失败）。

### FR-6 工业级 Barge-in 打断机制

- FR-6.1 系统在任一有音频输出的状态（应答语、回复播报、任务结果播报）均须能检测并响应打断；例外为：`barge_in.mode=disabled` 的半双工兜底（FR-6.5）、`wakeword.standby.announce=true` 的待机播报（FR-14.16）、高风险工具二次确认播报（FR-9.10，该轮语音作为确认回答处理）；无音频输出的思考阶段不涉及打断判定。
- FR-6.2 打断判定须采用多级策略，且须同时满足能量、持续时长、保护窗口等条件，避免误打断。
- FR-6.3 从打断判定成立到扬声器静音，须在 **300ms 内**完成（P95）。
- FR-6.4 打断后须完成完整清理：停止播放、取消 LLM 生成、取消 TTS 合成、清空播放队列、丢弃陈旧事件、归档当前轮次、恢复聆听。
- FR-6.5 须抑制「自打断」：
  - AEC 须为**可配置项**（`audio.aec.mode`）：`auto`（默认）/ `hardware` / `software` / `none`；
  - `auto` 下：机型 Profile 声明具备硬件回声消除（含波束成形）时使用**设备自带能力**，未声明或探测不可用时**自动启用软件 AEC**，并在状态与日志中明确记录当前生效模式；
  - 无硬件能力时须叠加多重软件手段：软件回声消除（以即将播放的音频为参考信号）、播报期门限提升、播放起始保护窗口、文本相似度回声剔除；
  - 须提供关闭打断（退化为半双工）的兜底开关，以适配极端噪声场景；
  - 播放起始保护窗口的默认值须随 AEC 生效模式自适应（hardware / software / none 分别取 100 / 200 / 300 ms），允许配置覆盖，不得与 AEC 模式完全解耦而固定不变。
- FR-6.6 打断事件须被记录（触发原因、各阶段耗时、是否发生回声抑制），并可在 WebUI 查看。
- FR-6.7 打断相关的全部阈值须可配置，且支持运行时热更新，便于现场调参。
- FR-6.8 被打断的轮次须被正确归档：用户输入完整写入；助手消息只写入**已送入播放队列的文本片段**（不写入未播出的生成内容），并标记 `status=interrupted` 与已播比例；未播出的完整生成内容仅进入事件日志 / 调试轨迹，不进入对话记忆。

### FR-7 稳定状态机与会话编排

- FR-7.1 会话须由显式状态机驱动，状态集合、事件集合、转移规则必须固定、可枚举、可审查。
- FR-7.2 **除常驻等待状态外，每一个状态都必须有超时兜底**，系统中不得存在无超时等待，杜绝卡死；常驻等待状态（`IDLE` 待机态、关闭唤醒词时的 `ACTIVE_IDLE`）不设状态超时，但须由全局看门狗心跳保护（FR-7.7）。
- FR-7.3 非法状态下收到非法事件时须忽略并告警，不得引发异常或崩溃。
- FR-7.4 状态转移须为原子操作，带守卫条件，并可审计（记录来源状态、目标状态、触发事件、轮次、耗时）。
- FR-7.5 系统须维护「当前有效轮次」，非当前轮次的一切事件（识别、生成、合成、播放）必须被丢弃，杜绝乱响应。
- FR-7.6 取消行为须能传播到全部下游任务，形成完整取消链路。
- FR-7.7 须提供全局心跳看门狗（默认 1s 检测无进展）并触发自恢复。心跳进展以音频帧到达、VAD / KWS 推理产出、事件处理与 provider 健康探测为判据；待机态与常开聆听态不得因「无对话事件」被误判为无进展。自恢复行为固定为：取消当前轮次的对话链路（LLM 生成、TTS 合成、播放队列）→ 复位状态机到 `IDLE`（关闭唤醒词时回 `ACTIVE_IDLE`）→ 保留已持久化记忆、将未完成轮次标记 `aborted` → 记录 ERROR 日志与 `watchdog_recovered` 指标、推送 WebUI 告警；已移交执行层的异步任务不得被看门狗取消（FR-9.5、FR-14.15），继续执行并按 FR-14.16 规则播报结果。不得自动重放被中断的请求。
- FR-7.8 须提供手动强制复位能力，供现场运维在异常时使用。

### FR-8 多轮对话记忆

- FR-8.1 须按会话维度维护多轮对话历史（用户、助手、工具调用消息）。
- FR-8.2 须支持按上下文预算进行滑窗裁剪，保证不超出模型上下文窗口。
- FR-8.3 须支持可选的滚动摘要记忆，使长对话的早期内容仍可被引用。
- FR-8.4 须支持会话生命周期管理：创建、查询、导出、清除、过期回收。
- FR-8.5 被打断的轮次须按策略写入记忆，保证用户被截断的提问不丢失。
- FR-8.6 记忆存储须可插拔替换。
- FR-8.7 （P2）须支持可选的长期记忆：用户偏好与事实的抽取与召回。

### FR-9 语音任务指令与执行

- FR-9.1 LLM 须通过 Function Calling 输出结构化任务指令，而非直接执行文本。
- FR-9.2 须提供工具注册机制，工具的名称、描述、参数约束、风险等级、超时均可定义。
- FR-9.3 执行适配方式须可插拔，本期至少覆盖**机器人控制**（ROS2 service / action）；IoT 设备控制（MQTT 等）暂不实现，仅保留扩展点，待具体需求明确后再纳入（A6）。
- FR-9.4 高风险指令（如移动、上电、写操作）须经策略校验或二次确认后方可执行。
- FR-9.5 长耗时任务须异步执行，执行期间不得阻塞用户继续对话。
- FR-9.6 任务执行结果须回灌给 LLM，生成自然语言播报反馈。
- FR-9.7 工具执行须支持超时与取消，失败时须播报明确的失败原因。
- FR-9.8 须具备指令白名单 / 黑名单与参数校验，防止越权或危险操作。
- FR-9.9 长耗时任务与待机会话窗口的协作规则见 FR-14.15 / FR-14.16：任务执行期间不得因会话回待机而被取消，结果播报规则须与活跃窗口联动。
- FR-9.10 **二次确认交互**：高风险工具须先播报确认问题并等待用户回答。该确认问题播报期间不启用 Barge-in，语音作为确认回答处理（由规则或 LLM 判定「确认 / 取消」），不新建对话轮次、不取消该待执行任务；等待超时（`tools.confirm_timeout_ms`，默认 10s，可配）或回答无法判定时按取消处理并播报结果，不得默认执行。

### FR-10 可插拔 Provider 与配置体系

- FR-10.1 须为模型能力（ASR / LLM / TTS / VAD / 唤醒词 / 知识库检索）、音频链路与设备适配、记忆存储、工具执行定义统一抽象接口（分别对应 FR-2.6、FR-4.8、FR-14.7、FR-16.1）。
- FR-10.2 新增一个模型厂商须只需：实现接口 + 注册驱动 + 增加配置段，**不得改动会话编排与状态机代码**。
- FR-10.3 配置须采用「驱动名 + 驱动参数」结构，并支持环境变量覆盖以注入密钥。
- FR-10.4 驱动须声明自身能力（是否流式、是否支持工具调用、是否支持热词、采样率等），编排层须据此自动降级功能。
- FR-10.5 须支持运行时不中断服务地热切换驱动。
- FR-10.6 须提供驱动健康检查与连通性测试能力。
- FR-10.7 须提供熔断与降级：主驱动连续失败达阈值后熔断，自动切换备用驱动或使用兜底话术，并在恢复后自动回切。默认阈值为「30 秒窗口内连续 5 次失败」、冷却 30 秒，按 CLOSED / OPEN / HALF_OPEN 状态机运行，阈值可配置。
- FR-10.8 配置变更须经校验与预检后方可生效；校验失败须拒绝并给出明确原因；须支持回滚到上一版本配置。
- FR-10.9 配置文件须与容器镜像分离，支持挂载覆盖，使同一镜像可部署到不同现场。
- FR-10.10 密钥不得出现在配置文件中，须通过环境变量或密钥文件注入，且不得在日志或 WebUI 中明文显示。

### FR-11 WebUI 控制台

- FR-11.1 实时会话面板：状态机状态可视化、音频活动指示、ASR 流式转写、LLM 流式文本、播报状态、打断事件时间线。
- FR-11.2 运行控制：开始 / 结束会话、手动打断、麦克风静音、文本输入兜底（无麦克风时可用键盘对话）；待机态下 WebUI 手动开始会话与文本输入须能直接激活会话（视作一次显式唤醒并开启活跃窗口），不得要求先说唤醒词（FR-14.4）。
- FR-11.3 模型配置页：查看与切换驱动、编辑参数、连通性测试、应用与回滚。
- FR-11.4 任务与工具页：工具列表（含风险等级）、调用历史、参数与执行结果。
- FR-11.5 记忆管理页：会话列表、历史消息查看、清除单轮 / 整会话、记忆策略配置。
- FR-11.6 监控页：各阶段延迟分位数、打断成功率、错误率、状态流转日志。
- FR-11.7 运维诊断入口：一键自检、音频回环测试、强制复位、日志导出。
- FR-11.8 WebUI 须支持局域网内由 PC / 平板浏览器访问，并对写操作进行鉴权：会话空闲 30 分钟失效，连续 5 次认证失败锁定 5 分钟，访问口令长度不得少于 8 位。

### FR-12 可观测性与稳定性

- FR-12.1 须输出结构化日志，日志须包含会话、轮次、状态、事件、耗时等字段，便于集中检索。
- FR-12.2 须采集分阶段延迟指标并以分位数形式暴露。
- FR-12.3 须记录会话全链路事件，支持导出与回放，用于问题定位。
- FR-12.4 须对异常分级处理：可恢复异常自动重试 / 降级；不可恢复异常进入错误状态并触发自恢复流程。
- FR-12.5 须对所有内部队列设置上限，超限时按策略丢弃并告警，禁止无界内存增长。
- FR-12.6 须支持优雅启停：收到停止信号后完成当前轮次并释放音频与模型连接。

### FR-13 部署与运维支持

- FR-13.1 系统须以容器镜像形式交付，可在机器人本体与机器人既有 ROS2 环境共存运行。
- FR-13.2 须提供一键部署能力（镜像拉取 / 构建 + 服务编排 + 启动），并支持开机自启动。
- FR-13.3 须提供服务健康检查与就绪探测，供编排系统与运维人员判断服务状态。
- FR-13.4 须提供启动自检能力：校验配置、检查 ROS2 连通性、检查模型服务可用性、检查磁盘与资源水位，输出明确结论。
- FR-13.5 须提供现场诊断命令：驱动连通性测试、音频回环测试、状态查询、强制复位。
- FR-13.6 须支持配置与数据的持久化与备份，容器重建后配置与历史数据不丢失。
- FR-13.7 须支持版本化升级与快速回滚。
- FR-13.8 须限制资源占用（CPU / 内存上限），避免影响机器人其他业务。
- FR-13.9 须控制镜像体积与依赖规模，遵循轻量化原则（详见 CON-1）。
- FR-13.10 关键依赖服务（本地 ASR / TTS 与远端 LLM / KB）须可独立部署与重启，其故障不得导致主服务崩溃；运行时健康检查须在 30 秒内发现服务崩溃并按 FR-10.7 熔断 / 降级（启动自检只覆盖启动时刻）。
- FR-13.11 **算力分层部署（A5 已确认）**：ASR / TTS 模型**默认以独立服务部署在机器人本体**（独立容器或宿主机进程，不得内置于应用镜像）；机型算力不足或明确配置降级时，允许 ASR / TTS 走边端 / 云端。VAD / KWS 为随镜像交付的两类轻量 ONNX 资产（进程内推理，CON-1、FR-14.11），AEC 为进程内 NumPy 实现（无模型文件）。LLM 与知识库**默认部署在边端或云端**，其地址、模型名、鉴权均可配置；仅在机型明确具备大算力且显式开启时，才允许 LLM 放在本体（拓扑 2）。边端 / 云端不可达时须在 30s 内降级（兜底话术；本地小模型仅在拓扑 2 或显式开启本机 LLM 时可用），不得卡死会话。
- FR-13.12 须提供算力与资源自检：本体侧报告模型服务实际资源占用与余量，提醒是否超出机器人可用资源。
- FR-13.13 **拓扑 2 故障降级**：本地 LLM 超时 / 崩溃 / OOM 时须按 FR-10.7 熔断；配置了边端或云端备用 LLM 时自动切换并告警，未配置时进入 `DEGRADED` 并使用兜底话术，30 秒内完成；本地 LLM 须设 cgroup 上限，不得挤占语音链路资源。

### FR-14 唤醒词与待机唤醒

> B-06 已确认：**需要唤醒词**。

- FR-14.1 系统须支持**本地**唤醒词检测，待机态常开运行，不得依赖云端、不得上传音频。
- FR-14.2 唤醒词须可配置（支持自定义唤醒词，支持配置多个唤醒词），更换唤醒词无需改动业务代码；自定义唤醒词仅支持导入预训练 KWS ONNX 模型资产，不支持由文本训练生成（见 §7.2 非目标）。
- FR-14.3 唤醒命中后须给出明确反馈（提示音或应答语），使用户确认已被唤醒。
- FR-14.4 唤醒后进入**会话活跃期**，活跃期内无需重复唤醒即可多轮对话、随时插话与打断；活跃窗口时长可配置（默认 60s），每轮交互后刷新；WebUI 手动开始会话与文本输入可替代唤醒词激活会话（FR-11.2）。
- FR-14.5 会话活跃期超时且无有效交互时，须自动回到待机态，并释放 ASR 会话等资源；关闭唤醒词（FR-14.8）时不适用本超时规则。
- FR-14.6 须具备防误唤醒机制：置信度阈值、命中冷却时间、可选二次确认，三者均可配置；标定后误唤醒率须 ≤ 2 次 / 30 分钟（对应 C-145）。
- FR-14.7 唤醒词检测引擎须可插拔替换（抽象为 `WakeWordProvider`），与 ASR / LLM / TTS 驱动同等的可插拔级别。
- FR-14.8 须支持关闭唤醒词、退化为常开聆听模式（用于特定现场或调试），切换通过配置生效；该模式下不触发活跃窗口超时，始终停留在 `ACTIVE_IDLE` 并保持 ASR 会话可用（否则无法再被唤醒），空闲资源指标按常开聆听模式单独实测。该模式默认须使用**本地 ASR 驱动**；若显式改用云端 ASR，须同时置 `wakeword.open_ear.cloud_asr_ack=true`（默认 false）明确确认，配置校验未通过时 FAIL 阻塞启动；置位后启动自检须 WARN 提示「音频将持续上传至云端」，并记录上传时长指标（CON-5、CON-6）。
- FR-14.9 **会话活跃期内的打断不得要求唤醒词**：用户说话即可打断，保障「秒打断」体验不被唤醒机制破坏。
- FR-14.10 唤醒不得显著增加端到端响应延迟：唤醒命中到唤醒反馈 ≤ 500ms；唤醒后可预连接 ASR 以降低首响（预连接可配置）。
- FR-14.11 唤醒词检测须为轻量实现：纯 CPU 可运行，空闲时 CPU 占用满足 NFR-3；模型资产须满足轻量化约束（CON-1：镜像内仅容许 VAD 与唤醒词两类小体积 ONNX）。
- FR-14.12 待机态下 ASR 会话须关闭或休眠；仅在唤醒后建立/激活，避免持续消耗算力与云端费用；关闭唤醒词（FR-14.8）时不存在待机态，ASR 常开。
- FR-14.13 唤醒状态与检测结果须可观测：唤醒次数、误唤醒次数、唤醒响应耗时可在 WebUI 与指标中查看；指标只允许上报计数与耗时，不得包含唤醒词原始音频或被唤醒片段（CON-6）。
- FR-14.14 唤醒词须支持多语言配置：至少提供中文与英文唤醒词，允许为方言配置发音变体（FR-15.7）。
- FR-14.15 **长任务与活跃窗口联动**：活跃期内，活跃窗口计时器在任务发起时刷新一次、结果播报完成后再刷新一次；任务执行期间不刷新。任务执行时长超过活跃窗口时，系统照常回 `IDLE`（关闭唤醒词时无活跃窗口超时，FR-14.8），任务在后台继续（FR-9.5），不得因回待机取消任务。待机态下的结果播报不刷新窗口，按 FR-14.16 处理。
- FR-14.16 **待机态任务结果播报**：默认不直接语音播报——缓存结果 + 可选提示音（不拉起 ASR），并在 WebUI 提示；用户下次唤醒后优先播报并刷新活跃窗口。若配置 `wakeword.standby.announce=true` 允许待机播报，则播报期间不拉起 ASR、不支持 Barge-in（半双工），播报结束仍回 `IDLE`。关闭唤醒词（FR-14.8）时不存在待机态：结果直接按活跃期规则语音播报且支持 Barge-in，本条的缓存与 `standby.announce` 均不适用。
- FR-14.17 **多唤醒词命中冲突**：多个唤醒词同时命中时取置信度最高者；置信度相同时取配置顺序第一个；同一唤醒窗口内只触发一次，冷却期内不重复唤醒。

### FR-15 多语种与方言支持

> A8 已确认：支持**中英两种语言**，以及**粤语、东北话、武汉话、上海话、天津话** 5 种方言。

- FR-15.1 须支持中文（普通话）与英文两种语言；支持中英混说整句识别（FR-3.8）。
- FR-15.2 须支持粤语、东北话、武汉话、上海话、天津话 5 种方言的语音识别。
- FR-15.3 语言 / 方言须支持两种工作模式：**固定模式**（配置锁定，适合单一场景）与**自动模式**（依据识别结果自动判定并记录）。
- FR-15.4 须支持会话内切换：用户直接用另一种语言说话时无需重开会话，系统自动跟随并更新 `lang`；自动模式须防抖（默认连续 2 句或累计 ≥ 6 字符一致才切换），单句噪声误识别不得切语言；**同一 ASR 驱动内**切语言不得重建热流、不得引入额外首响；**跨驱动切换**（如本地 `zh` → 云端方言）允许一次受控重连，但须在防抖判定期间预连接目标驱动，切换后首响不得劣于 NFR-1（FR-15.11）。
- FR-15.5 ASR / TTS 驱动须在 capabilities 中声明支持的语言集合；编排层按声明选路，驱动不支持目标语言时须降级到 `zh` 并告警，不得静默返回错乱文本。
- FR-15.6 TTS 须按 `lang` 选择音色；方言无法合成时降级为普通话并明确标记（FR-5.7）。
- FR-15.7 唤醒词须支持多语言 / 方言变体配置，至少覆盖中文与英文唤醒词。
- FR-15.8 方言识别由**外置模型服务**提供（如 FunASR 方言模型或云端方言 ASR）；应用镜像不内置方言模型（CON-8）。
- FR-15.9 WebUI 须展示当前识别语种 / 方言，并允许运维切换固定语言或设为自动。
- FR-15.10 每个轮次须记录 `lang`；记忆与工具调用在跨语言场景下保持可用（用户换语言后仍能理解上下文）。
- FR-15.11 多语言不得破坏延迟指标：NFR-1 的指标须按语言分别达标（走云端 ASR 的语言按云端 ASR 档，见 NFR-1）。
- FR-15.12 语言能力与选路结果须可观测：各语言识别成功率、降级次数、切语言次数可在指标中查看。
- FR-15.13 **中英混说的 `lang` 判定**：整句识别时按字符占比判定主语言——任一语言占比 ≥70% 时判为该语言；无任一语言达到 70%（含占比接近 50% 的均衡句）时沿用会话当前 `lang`，不得按语言切段（FR-3.8）。
- FR-15.14 **TTS 降级后的语言标记**：方言音色缺失降级普通话时，`lang` 保留识别语言用于统计，另记 `tts_lang=zh`、`tts_fallback=true`；提示词须要求以普通话书面语生成，禁止生成方言文本，避免「方言文本 + 普通话音色」错配。本条在 `tts_fallback=true` 时优先于 FR-4.6 的「同方言回应」要求。
- FR-15.15 **方言服务运行时故障**：方言 ASR 模型服务不可达 / 超时时，退回 `zh` 驱动识别本轮音频，`lang=zh`，记录 `language_fallback_count` 并在 WebUI 告警；连续失败达阈值按 FR-10.7 熔断该方言驱动，不得静默返回错乱文本。

### FR-16 机器人音频设备抽象与多机型适配

> A1/A2 已确认：不同机器人型号的 ROS2 麦克风采集接口与扬声器播报方式**均不一样**，因此必须由系统提供设备抽象层，再由各机型单独适配实现。
>
> **适配机型范围（2026-11-01 确认，5 款配置均须交付）**：智元灵犀 X2（Pro 探索版）、智元灵犀 X2（Ultra 旗舰版）、智元 A2、智元 A3、宇树 G1。同一型号的不同版本按独立配置（Profile）处理，不得以一版配置代替另一版。

- FR-16.1 须提供设备抽象层 `AudioDeviceAdapter`，将「采集」与「播放」拆分为两个独立契约；上层（VAD / ASR / KWS / 播放队列 / Barge-in）只依赖抽象接口，不得直接依赖具体话题名、服务名或消息类型。
- FR-16.2 每个机器人型号须以**配置化 Profile**（`config/devices/<model>.yaml`）描述其接口细节：话题 / 服务名称、消息类型与字段、采样率、位深、声道数、帧长、编码、QoS、时间戳语义、设备标识。上述内容禁止硬编码在业务代码中。
- FR-16.3 须提供 Profile 注册与选路：启动时按 `audio.device_profile` 加载对应 Profile（可选自动探测）；**同一镜像**须能通过切换 Profile 服务不同机型，不得因换机型重新构建镜像。
- FR-16.4 须提供能力声明与启动校验：Profile 须声明能力（采集 / 播放 / 回声参考 / 硬件 AEC / 音量控制 / 立即停播方式）；启动自检须校验 Profile 与现场实际话题 / 服务是否匹配，不匹配须 FAIL 并给出可操作提示，**不得静默启动**。
- FR-16.5 Profile 的采样率 / 声道 / 位深与内部管线不一致时，须由适配层完成转换；转换须使用带抗混叠的低通重采样（禁止最近邻 / 直接抽取），1 kHz 正弦测试 THD+N ≤ 1%，且不得使延迟超出 NFR-1。
- FR-16.6 播放须支持 `flush()` 立即停播语义（Barge-in 依赖 FR-6.3）；不同机型的停播方式（专用 service / topic 控制 / 音量归零 / 流中断）由 Profile 声明并实现。
- FR-16.7 新增机型适配只允许：新增 Profile + 新增或扩展适配器实现 + 补齐契约测试；**不得改动**状态机、编排器、VAD / ASR / LLM / TTS provider 代码（与 FR-10.2 同一原则）。
- FR-16.8 适配层须有统一契约测试套件（采集帧率与丢帧、播放出声、`flush()` 延迟、断线重连、时间戳单调性、采样率转换正确性），新机型接入须通过该套件方可交付。
- FR-16.9 Profile 缺失或非法（未知机型、缺必填字段、声明能力与实现不符）时，须在启动阶段报明确错误并拒绝进入就绪态，不得回落到猜测性默认值。
- FR-16.10 须提供设备诊断能力：列出已注册 Profile、探测现场实际话题 / 服务、逐项验证采集与播放、输出机型匹配结论。
- FR-16.11 **自动探测失败处理**：无法唯一匹配 Profile 时，若配置了 `audio.fallback_profile` 则使用并 WARN；未配置则 FAIL 拒绝进入就绪态并提示手工指定，禁止回落到猜测性默认值（FR-16.9）。
- FR-16.12 **首批适配机型交付范围**（2026-11-01 确认）：须交付以下 5 款配置，每款一份独立 Profile（`config/devices/<model>.yaml`）+ 所需适配器 + 契约测试通过：

  | 序号 | 机型 | 版本 / 说明 | 建议 Profile ID | ROS2 发行版 |
  | --- | --- | --- | --- | --- |
  | 1 | 智元灵犀 X2 | Pro 探索版 | `agibot_x2_pro` | 按 D12 现场采集 |
  | 2 | 智元灵犀 X2 | Ultra 旗舰版 | `agibot_x2_ultra` | 按 D12 现场采集 |
  | 3 | 智元 A2 | — | `agibot_a2` | 按 D12 现场采集 |
  | 4 | 智元 A3 | — | `agibot_a3` | 按 D12 现场采集 |
  | 5 | 宇树 G1 | — | `unitree_g1` | 按 D12 现场采集 |

  其中「ROS2 发行版」与「音频接口契约」（话题 / 服务、消息类型、采样率等）由 D12 清单逐机型采集后填入 Profile；**未取得清单的机型不得以猜测值交付**（FR-16.9）。每款机型须各完成一轮真实语音对话（C-177）方可验收。

## 6. 非功能需求

### NFR-1 延迟指标

语音侧指标在机器人本体测量；LLM 相关指标按部署位置分为「边端档 / 公网档」分别验收。均取 P95：

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| ASR Partial 延迟 | ≤ 300 ms | 用户说话到出现首个 partial |
| 尾点判定时长 | ≤ 700 ms（默认值，可配） | 用户静音起点 → 尾点判定完成；单独计量，不计入首响预算 |
| ASR Final 延迟 | ≤ 300 ms | 尾点判定完成 → final 产出 |
| LLM 首 Token | ≤ 800 ms（边端档 / 公网档） | 提交请求到首个 token |
| TTS 首音频 | ≤ 400 ms | 文本送入到首块音频可播放 |
| 端到端首响 | ≤ 1500 ms（边端档，本地模型链路）/ ≤ 1800 ms（公网档） | 尾点判定完成 → 扬声器出声 |
| **Barge-in 响应** | **≤ 300 ms** | 打断判定成立 → 扬声器静音 |
| 唤醒反馈 | ≤ 500 ms | 唤醒词命中 → 提示音 / 应答语开始播放 |

> 云端 ASR 档（含 `zh` / `en` 与方言，CON-5 / CON-9）：ASR Partial ≤ 600 ms、ASR Final ≤ 800 ms、端到端首响 ≤ 2000 ms（首响分项中的 ASR Final 由 800 ms 替代本地档的 300 ms）；本地 ASR 仍按上表执行。切语言不得引入额外首响延迟（FR-15.11）。
> 算力分层补充（A5）：LLM 部署在边端 / 云端时，上述指标须按「边端档」与「公网档」两档分别验收——边端档 LLM 首 token ≤ 800 ms、端到端首响 ≤ 1500 ms；公网档 LLM 首 token ≤ 800 ms、端到端首响 ≤ 1800 ms（网络抖动余量体现在端到端差额上）。知识库检索计入首响：800 ms 是「检索 + LLM 首 token」的**合计上限**，不是可叠加的两段预算——启用 RAG 时检索 ≤ 200 ms、模型首 token ≤ 600 ms；检索超时 / 失败被跳过时不占用预算，模型首 token 可用满 800 ms（FR-4.7）。
> 叠加关系：端到端首响 = ASR Final（本地 ≤ 300 ms / 云端 ≤ 800 ms，自尾点判定完成起算） + LLM 首 token + TTS 首音频。边端档（本地 ASR）300 + 800 + 400 = 1500 ms；公网档（本地 ASR）在分项之上预留 300 ms 抖动余量（≤ 1800 ms）；云端 ASR 档 800 + 800 + 400 = 2000 ms。尾点判定时长（≤ 700 ms）与端到端首响分别计量，不计入首响预算；用户从停止说话到听到回应的总时长 = 尾点判定时长 + 端到端首响。

### NFR-2 稳定性

- 连续运行 72 小时：无卡死、无状态机非法转移、内存增长 ≤ 5%（以「服务就绪完成时刻」的常驻内存 RSS 为基线，不含独立模型服务进程）。
- 单会话连续 1000 轮对话：不发生上下文溢出或状态错乱。
- 强制停止任一模型服务：系统在 30 秒内进入降级并给出明确播报；服务恢复后 30 秒内自动回切。若被停止的是 TTS 本身，降级提示改用提示音 + WebUI / 日志文本，不得依赖 TTS 播报。
- 所有状态在无外部事件时均不得超过配置的超时上限。
- 容器重启后服务可自动恢复，且历史会话数据不丢失。

### NFR-3 并发与资源

- 单实例须支持 ≥ 1 路实时会话（机器人本体默认场景），架构须支持扩展至 ≥ 5 路并发。
- 空闲时 CPU 占用 ≤ 10%（主要来自常开 KWS 唤醒词检测；VAD 在待机态降为低频能量门控）；对话中 CPU 占用 ≤ 70%。上述 CPU 指标以首批机型（D13 实测清单）为基准，验收须记录 ONNX Runtime 版本与参考芯片，不得跨机型直接套用。关闭唤醒词常开聆听（FR-14.8）时 KWS 不运行、VAD 与 ASR 热流常开，空闲 CPU 以该模式实测值单独记录，不套用 10% 上限。
- 常驻内存 ≤ 800 MB（不含独立的模型服务进程）。
- 应用容器须可设置 CPU / 内存上限（cgroup），超限不得影响宿主机其他业务。
- **本体模型预算（A5 已确认）**：本体侧需为 ASR / TTS 模型服务以及 VAD / KWS / AEC 运行时预留资源，须在部署前给出实测预算表（CPU 核数 / 内存 / 可选 GPU / NPU），且全部服务同时运行时不触发本体 OOM；LLM 与知识库不占本体资源。
- 本体资源不足时须支持「按需加载」（空闲卸载 ASR / TTS 或降为云端），不得静默超卖资源；关闭唤醒词（FR-14.8）时不得空闲卸载 ASR（否则失去唯一输入通道），TTS 仍可卸载。

### NFR-4 轻量化与交付

- 应用容器镜像（不含模型服务）体积按方案分档：方案 A（`ros:<distro>-ros-base` 基础镜像，容器内直连 DDS）≤ 1.6 GB；方案 B（`python:slim` + 宿主机桥接节点）≤ 800 MB。体积以 `docker images` 显示的镜像（解压后）大小为准，不含构建缓存与宿主机侧模型服务。
- 应用运行时不引入重型深度学习框架；除 VAD 与 KWS 两类轻量 ONNX 外，模型推理一律通过外部服务接入（详见 CON-1、FR-14.11）。
- 方言 ASR 模型与多语言 TTS 音色均属外置模型服务资产，不进入应用镜像（CON-8）。
- 镜像须按 ROS2 发行版分别构建（Humble / Jazzy），各自满足所采用方案对应的体积上限；不得以「一套镜像兼容所有发行版」为由放宽体积约束（CON-10）。
- 完整交付物须包含：镜像、编排文件、配置文件模板、机型 Profile 模板、自检脚本、部署与运维说明。
- 从零到可运行的目标：单条命令完成部署，5 分钟内服务就绪。

### NFR-5 安全与权限

- 云端 API Key 仅通过环境变量或密钥文件注入；禁止硬编码；禁止在日志与 WebUI 中明文展示。
- WebUI 须提供访问口令认证，写操作（配置变更、任务执行、强制复位）须鉴权；会话空闲 30 分钟失效、连续 5 次失败锁定 5 分钟、口令不少于 8 位（FR-11.8）。
- 工具调用须具备白名单与风险分级，高风险操作须二次确认。
- 容器须以非 root 用户运行，尽量缩小攻击面。
- 日志中不得输出密钥与用户原始音频数据。

### NFR-6 可维护性

- 新增模型驱动不得改动编排层与状态机（见 FR-10.2）。
- 代码须通过静态检查（类型检查 + 代码规范检查）。
- 状态机、取消传播、打断判定、记忆裁剪等关键逻辑须有单元测试；打断场景须有端到端测试。
- 关键参数（VAD、Barge-in、AEC、超时）须有集中配置与调优说明。

## 7. 约束与边界

### 7.1 硬约束

| 编号 | 约束 | 说明 |
| --- | --- | --- |
| CON-1 | 轻量化部署，避免重依赖 | 应用容器不得内置重型深度学习框架；本地模型作为独立服务通过 HTTP / WebSocket 接入；VAD 等端侧算法须选用轻量运行时 |
| CON-2 | Docker 容器 + ROS2 共存 | 系统以容器交付，须与机器人本体现有 ROS2 环境在同一网络与 DDS 域内协同工作，且不得破坏机器人既有 ROS2 功能 |
| CON-3 | 部署位置 | 系统运行在机器人本体（Linux ARM64） |
| CON-4 | 音频设备接入 | 麦克风阵列与扬声器通过 ROS2 对接 |
| CON-5 | 模型可本地可云端 | 本地模型服务与云端 API 均须支持，且可配置切换 |
| CON-6 | 唤醒词本地化 | 唤醒词检测须在机器人本体本地运行，不得依赖云端，不得上传唤醒检测阶段的原始音频（隐私与离线可用）；会话期云端 ASR 的音频传输仍按 CON-5 / CON-9 的云端驱动配置执行；指标上报仅限计数与耗时，不得包含音频片段 |
| CON-7 | 唤醒不破坏全双工体验 | 会话活跃期内打断不需要唤醒词；唤醒机制不得引入额外的打断延迟 |
| CON-8 | 多语言资源外置 | 方言 ASR 模型、多语言 TTS 音色须作为外置模型服务提供，不得进入应用镜像（轻量化） |
| CON-9 | 网络为内网但可访问公网（A9 已确认） | 允许使用云端 ASR / LLM / TTS；须具备离线自动降级到本地驱动的能力，不得因公网抖动导致会话卡死 |
| CON-10 | ROS2 双发行版（A3 已确认） | 机器人 ROS2 主版本为 **Humble**（Ubuntu 22.04 / Python 3.10）与 **Jazzy**（Ubuntu 24.04 / Python 3.12），两者均须支持；代码须兼容 Python 3.10 ~ 3.12，镜像按发行版分别构建与打标 |
| CON-11 | 设备适配层强制（A1/A2 已确认） | 音频设备接入必须经 `AudioDeviceAdapter` 抽象；机型差异只能通过 Profile + 适配器实现表达，禁止在业务代码中出现具体话题名 / 服务名 / 消息类型 |
| CON-12 | 算力分层（A5 已确认） | ASR / TTS 模型**默认**以独立服务部署在机器人本体（独立容器或宿主机进程，不进应用镜像）；VAD / KWS 为随镜像的两类轻量 ONNX、AEC 为进程内 NumPy（CON-1、FR-14.11）；**LLM 与知识库默认部署在边端或云端**；例外须显式配置：本体算力不足时可将 ASR / TTS 降级到边端 / 云端，机型明确具备大算力时可开启拓扑 2 将 LLM 放在本体，禁止默认就超卖本体资源 |
| CON-13 | AEC 能力差异化（A4 已确认） | 硬件 AEC / 波束成形是否存在因机型而异：有则使用设备自带能力，无则启用软件方案；`audio.aec.mode` 可配置，默认 `auto`，禁止写死为单一实现 |

### 7.2 非目标（Out of Scope）

- 模型训练、微调与量化（仅做推理接入）
- 麦克风阵列底层驱动与固件（由设备侧提供）
- 各机型 ROS2 采集 / 播放节点的开发（仅按其既有接口做适配接入，见 FR-16）
- 多租户 SaaS 化与计费
- 移动端 App（WebUI 仅需支持浏览器访问）
- **IoT 设备控制（A6 已确认）**：MQTT / 第三方设备协议接入本期不实现，仅在执行适配层保留扩展点；待具体需求明确后再纳入（见 FR-9.3、design §9.5）
- 唤醒词模型的训练与「文本生成唤醒词」（自定义唤醒词仅支持导入预训练 KWS ONNX 资产，不支持由文本训练生成）
- 方言语音模型的训练 / 微调与方言音色定制（仅接入现成模型与音色）
