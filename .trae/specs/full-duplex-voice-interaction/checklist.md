## 1. 全双工与打断（R1、R7）

| ID | 优先级 | 检查项 | 验证方式 | 通过标准 |
| --- | --- | --- | --- | --- |
| C-01 | P0 | 播报期间 ASR 持续工作 | 机器人播报时对麦克风说话，观察是否产出 partial | 播报期间持续产出 partial，无中断 |
| C-02 | P0 | 边听边说：播报中用户说话不被漏掉 | 在播报第 2 秒开始说话，说完后看机器人回应 | 用户话语被完整识别并正确回应 |
| C-03 | P0 | 秒打断：用户说话使播放立即停止 | 播报中说话，用高速录音或时间戳测量停播时刻 | 判定成立到扬声器静音 ≤ 300ms（P95） |
| C-04 | P0 | 打断后立即进入聆听 | 打断后继续说完一句话 | 状态转移到 `LISTENING` ≤ 150ms，识别到完整句子 |
| C-05 | P0 | 打断时上游被正确取消 | 打断后查看日志 | LLM 生成中止、TTS 合成中止、播放队列清空，均有取消日志 |
| C-06 | P0 | 打断后无「幽灵播报」 | 打断后静默 10 秒 | 扬声器不再输出任何残留音频 |
| C-07 | P0 | 防自打断 | 让机器人播报 30 秒长文本，全程不说话 | 无任何误打断；`echo_suppressed` 计数 > 0 |
| C-08 | P0 | 打断后不产生乱响应 | 连续打断 20 次，每次说不同内容 | 每次回应与最新用户话语对应，无张冠李戴 |
| C-09 | P1 | 打断后当前轮次正确归档 | 查看轮次记录 | `status=interrupted`，已播报文本被记录 |
| C-10 | P1 | 打断指标可视化 | WebUI 打断事件时间线 | 每次打断可见触发原因与各阶段耗时 |
| C-11 | P1 | 极端噪声下可退化为半双工 | 配置 `barge_in.mode=disabled` | 播报期间不打断，播报完成后恢复聆听 |

## 2. 状态机与稳定性（R6）

| ID | 优先级 | 检查项 | 验证方式 | 通过标准 |
| --- | --- | --- | --- | --- |
| C-20 | P0 | 状态集合与转移可枚举 | 代码审查 + 单测 | 采用显式转移表，无散落的 if/else 状态判断 |
| C-21 | P0 | 每个状态都有超时兜底 | 单测遍历全部状态；噪声阶跃测试 | 所有状态均声明超时；VAD 最大语音时长保护可强制端点（FR-2.5）；噪声阶跃后 3s 内门限收敛 ±3dB（FR-2.2）；启动时校验通过（INV-2） |
| C-22 | P0 | 超时后能自动恢复 | 桩掉 LLM 不返回，观察 | 首 token 超时后进入降级、播报兜底话术，不卡死；可恢复异常自动重试 / 降级，不可恢复异常进入 ERROR 并触发自恢复（FR-12.4） |
| C-23 | P0 | 非法事件被忽略且告警 | 单测：在 `IDLE` 注入 `EV_ASR_FINAL` | 无异常抛出，记录告警，状态不变 |
| C-24 | P0 | 陈旧事件被丢弃 | 单测：用旧 turn_id 注入事件 | 事件被丢弃并计数，不污染当前轮次（INV-1） |
| C-25 | P0 | 取消传播完整 | 单测：触发取消并检查各下游 | LLM / TTS / 播放 / 工具均收到取消；ASR 采集流保持（INV-3） |
| C-26 | P0 | 72 小时长稳 | 持续运行 72h，含 1000+ 轮对话与随机打断；记录就绪完成时刻 RSS 基线 | 无卡死、无非法转移、内存增长 ≤ 5%（以就绪完成时刻 RSS 为基线，不含模型服务进程） |
| C-27 | P0 | 看门狗生效与恢复行为 | 人为使某协程挂起，检查状态、记忆与告警；另在长任务执行期间触发看门狗 | 1s 心跳检测到无进展；自恢复后回 `IDLE`（关闭唤醒词时 `ACTIVE_IDLE`），当前轮次 `aborted`、已持久化记忆保留，出现 `watchdog_recovered` 与 WebUI 告警；已移交执行的异步任务不被取消、继续完成后按 FR-14.16 播报；不自动重放请求（FR-7.7、FR-9.5）；待机态（`IDLE`）与常开聆听态（`ACTIVE_IDLE`）静置 10 分钟（仅有音频帧与 VAD / KWS 推理产出、无对话事件）不得被判无进展而触发自恢复（FR-7.7） |
| C-28 | P0 | 队列有界 | 代码审查 + 压测灌入 | 所有内部队列有上限，超限丢弃并告警，无 OOM（INV-7） |
| C-29 | P1 | 优雅启停 | 发送停止信号 | 完成当前轮次后释放 ROS2 与模型连接，无残留进程 |
| C-30 | P1 | 强制复位可用 | 调用 `cli session reset` | 异常状态下可恢复到可用状态 |

## 3. 流式链路与延迟（R2）

| ID | 优先级 | 检查项 | 验证方式 | 通过标准 |
| --- | --- | --- | --- | --- |
| C-40 | P0 | ASR 流式 partial | 指标采集 | 说话后 ≤ 300ms 出现首个 partial（P95） |
| C-41 | P0 | LLM 流式首 token | 指标采集（分别关闭 / 开启 RAG） | 边端档 / 公网档均 ≤ 800ms（P95）；启用 RAG 时「检索 + 首 token」合计 ≤ 800ms（检索 ≤ 200ms、模型首 token ≤ 600ms）；检索被跳过时模型首 token 可用满 800ms（NFR-1、FR-4.7） |
| C-42 | P0 | TTS 流式首音频 | 指标采集 | ≤ 400ms（P95） |
| C-43 | P0 | 端到端首响 | 指标采集（同时记录尾点判定时长） | 边端档 ≤ 1500ms、公网档 ≤ 1800ms、云端 ASR 档 ≤ 2000ms（P95；以尾点判定完成时刻为计时起点）；云端 ASR 档另需 Partial ≤ 600ms、Final ≤ 800ms；尾点判定时长单独 ≤ 700ms（默认配置，可配）；知识库 200ms 预算含在 LLM 首响内（NFR-1） |
| C-44 | P0 | LLM 首 token 即触发 TTS | 代码审查 + 事件日志 | 非整句生成完才合成 |
| C-45 | P0 | 按句切分策略生效 | 观察长回复播报 | 长回复逐句流出播放，非一次性等待 |

## 15. 意图识别与路由（R14、FR-17、NFR-1）

> A12 已确认默认 6 类意图（`chat` / `knowledge` / `command` / `confirm` / `cancel` / `stop`），判定方式为「本地规则快速路径 + 可插拔语义分类驱动」，阈值默认 0.6。本节验证「分类正确、不阻塞首响、不误触发控制、可配置可观测」。
> 设计依据：design §9.6、ADR-18；关联 C-80 ~ C-84（工具链路）、C-41 ~ C-43（首响）。

| ID | 优先级 | 检查项 | 验证方式 | 通过标准 |
| --- | --- | --- | --- | --- |
| C-178 | P0 | 意图结果结构完整且意图集合可配置 | 审查 `IntentResult` 与 `config/intent.yaml`；新增一个测试意图后重启 / 热更新 | 每轮产出 `intent` / `confidence` / `slots` / `source` / `latency_ms`；意图取值来自配置，代码中无硬编码业务枚举；新增意图不需改状态机与编排（FR-17.1、FR-17.2） |
